# NEAR wallet manual verification

Quorumark uses the maintained NEAR Wallet Selector on testnet. The selector currently includes Meteor Wallet and My NEAR Wallet; only a wallet that returns a NEP-413 message signature can complete authentication.

## Meteor Wallet flow

1. Open Meteor Wallet, select NEAR testnet, and make sure `estarkunmi.testnet` is selected.
2. Start Quorumark locally with `npm run dev`, then open `/connect-wallet`.
3. Choose **Connect NEAR Wallet** and select **Meteor Wallet** in the native selector. Do not enter a seed phrase into the application.
4. Approve the clearly labelled Quorumark authentication message in Meteor Wallet.
5. Confirm that Quorumark displays the returned account and `meteor-wallet · near:testnet`, then open the marketplace.
6. Use **Switch wallet** to sign out of the current wallet and select another wallet. Use **Sign out** to clear the Quorumark session and the selector wallet session.

The browser automation suite can verify the selector and all server-side rejection cases, but it cannot approve a real extension prompt. A real-wallet result is only recorded after Meteor signs the challenge and the deployed `wallet-verify` function accepts that signature.

## Security checks

The challenge is generated by the server and is bound to the Quorumark recipient, NEAR testnet, account, one-time nonce, and expiry. Reusing the same challenge, changing the account, or submitting an invalid signature must be rejected by the deployed verifier.
