# Aster regional egress

This package provides an isolated WireGuard network namespace for a future
TurtleBot Aster execution service. It does **not** enable Aster trading by
itself. TurtleBot's current production execution path remains ApeX-only.

## Boundary

- The browser never joins the tunnel.
- Wallet private keys and exchange secrets never enter the probe container.
- ApeX broker and signer traffic retain their existing route.
- Only a future Aster executor may share the WireGuard network namespace.
- Configuration fails closed unless `ASTER_JURISDICTION_APPROVED=true`.
- The health probe is locked to Aster's official Futures API origin and cannot
  be repurposed as an arbitrary URL proxy.

Use this only where the company, account, and selected server jurisdiction are
permitted to access Aster. It is not a location-obfuscation feature.

## Prerequisites

1. A Linux execution host that permits `NET_ADMIN` and `/dev/net/tun`.
2. A WireGuard server/exit node in an approved region.
3. A client configuration generated by that server.
4. Docker Engine with Compose v2.

The WireGuard software is open source. Server hosting and bandwidth are not
free unless an existing eligible host is available.

## Configure

From `infra/aster-egress`:

```sh
cp .env.example .env
mkdir -p config/wg_confs state
chmod 700 config state
```

The `PUID` and `PGID` values in `.env` must own `state/`; the probe runs under
that identity and never needs root access.

Place the client configuration at:

```text
config/wg_confs/wg0.conf
```

The file must contain a client private key and an `AllowedIPs` route supplied
by the operator's WireGuard server. Never commit it. The repository ignores the
entire runtime `config/` and `state/` trees.

After eligibility and server jurisdiction have been verified, set:

```text
ASTER_JURISDICTION_APPROVED=true
```

## Verify without trading

```sh
docker compose config
docker compose up -d
docker compose ps
docker compose logs --tail=50 aster-probe
```

Healthy output is exactly:

```text
aster-egress: healthy
```

The probe calls only Aster's documented unauthenticated connectivity endpoint:

```text
GET https://fapi.asterdex.com/fapi/v3/ping
```

No account, wallet, signing, order, or position endpoint is called.

## Production image pinning

The Compose file pins both images to immutable multi-architecture digests
resolved on 2026-09-17. To deliberately upgrade them, inspect the new tags from
the deployment host:

```sh
docker buildx imagetools inspect lscr.io/linuxserver/wireguard:latest
docker buildx imagetools inspect curlimages/curl:8.12.1
```

Replace each Compose digest only after reviewing the new manifest, then rerun
`docker compose config` and the unauthenticated connectivity probe.

## Aster executor integration gate

Do not attach order execution until all of these are implemented and tested:

1. An Aster-specific connection and credential type; no reuse of ApeX rows.
2. Envelope-encrypted Aster credentials in the signer service.
3. Venue-specific symbol, precision, leverage, margin, and position-mode rules.
4. Read-only balance, position, order, and fill reconciliation.
5. Idempotent client order IDs and ambiguous-outcome reconciliation.
6. Per-connection live flag plus operator-level signer, canary, and automation
   gates that default off.
7. Aster adapter tests using fixtures before any authenticated request.
8. One manual, minimum-size canary with autonomous execution still disabled.

When the executor exists, add it as a Compose service with:

```yaml
network_mode: service:wireguard
```

That scopes Aster egress to the executor rather than routing the entire
TurtleBot application through the tunnel.
