# SynFutures transaction recovery

This change implements durable receipt recovery, **not live activation**. It
does not deploy a Safe/module, fund it, approve tokens, grant an operator session,
or sign/send an order. Existing ApeX/Aster paths and the UI remain unchanged.

## Connected path

`POST /v1/synfutures/reconcile-orders` on the broker authenticates the owner JWT,
checks the selected connection under RLS, and calls the private signer's fixed
HMAC-authenticated route. The signer uses worker-ingest's signed narrow journal
operations. It never needs a Supabase service key or wallet private key to read
receipts. `TURTLEBOT_BASE_RPC_URL` must be configured on the signer and support
the `finalized` block tag. No request can override the URL or target addresses.

The child journal references the existing `order_intents` authority. Integer
amounts/nonces cross JSON as strings. Reservation atomically validates the
intent's owner, connection, venue, network, market, side, exact size and reduce-only
flag; binds a transaction hash; and locks unresolved operator/module lanes.
Repeated reservation never grants a second send attempt. Receipt observations
update journal + intent in one database transaction. RLS permits only owner
reads; authenticated/anonymous callers cannot write or call the journal RPCs.

## Receipt proof

Require Base chain ID 8453; the exact hash, sender, target, operator nonce and
zero native value; a canonical receipt block at or below the finalized height;
and exactly one matching module `TradeExecuted` event. Match revision, module
nonce, instrument, signed size, margin and reduce-only flag without rounding.
The event is emitted by the PR68 module only after its position-delta checks.
The final runtime must verify that deployed module bytecode before reservation.

Missing receipt, unfinalized block, changed block hash, removed/mismatched event,
or unavailable RPC => unresolved, never a synthetic fill or retry. A finalized
status-0 receipt records a reverted transaction. A database failure cannot be
reported as successful reconciliation. No fill price, fee or P&L is invented.

## Remaining before live testing

- Integrate the reviewed Safe module (PR68), deploy/verify it, and bind the
  verified owner Safe, module, operator and session to the exchange connection.
- Implement the private transaction compiler/signing/submission adapter. It must
  persist hash/metadata before broadcast, proceed only on `created=true`, and
  leave ambiguous sends for this recovery path, not build a replacement order.
- Wire reconciliation into the worker's periodic SynFutures cycle. The broker
  route exists but this change does not introduce background polling or entries.
- Finish protective exits and position/fee reconciliation. The current journal
  serializes unresolved transactions until finality; **do not activate automated
  entries with this alone**. Exit handling must not strand a position while an
  earlier entry is included but not finalized. Session expiry/revocation and RPC
  loss also require explicit protection behavior and owner visibility.
- Fork-test the complete lifecycle with real module bytecode, then obtain the
  owner's wallet deployment/session/funding approvals. No mainnet signature has
  been requested or generated by this change.

## Tests

`python -m unittest discover -s tests -p test_synfutures_reconciliation.py` from
`signer/` runs dependency-free receipt tests. Authoritative signer CI uses the
locked Python 3.11 environment. Broker tests exercise identity, injection,
upstream failure, and unresolved-status propagation. The journal PGlite fixture
runs in lifecycle CI and verifies replay, exact integers, atomic observations,
ownership, and privilege boundaries without production access.
